【一、这是什么】
────────────────────────────────────────────
Sparrow Wallet 是一款专注安全与隐私的开源桌面比特币钱包。原版软件没有
多语言机制，界面文字 100% 硬编码在程序内部（31 个界面布局文件 FXML 与
400 余个 Java 类中）。

本项目对其做了「完整中文汉化」，并提供三样东西：
  1) 已汉化、可直接运行的程序（绿色便携，任意目录解压即用）；
  2) 可回滚的原始镜像与还原脚本；
  3) 一条纯 Python（无需安装 JDK）的一键构建工具链与可扩展翻译字典，
     今后 Sparrow 升级新版本时，可在几分钟内用同一套脚本重新汉化。


────────────────────────────────────────────
【二、如何使用（三种方式）】
────────────────────────────────────────────
方式 A：直接用中文便携版（最简单）
  解压 Release 的“Sparrow-中文便携版.zip”到任意目录（中文/空格路径均可），
  双击 Sparrow.exe 即为中文界面，免安装、免联网、免额外环境。

方式 B：双击“一键汉化.bat”（给本机已装的英文 Sparrow 打补丁）
  1. 先装 Python 3.8 或更高版本（安装时勾选 Add Python to PATH）；
  2. 双击 中文补丁\一键汉化.bat；
  3. 按提示把 Sparrow 安装文件夹拖进窗口（或回车自动探测），选择是否装回；
  4. 首次会在镜像旁生成 modules.original.bak（原始英文版，用于还原）。

方式 C：命令行一键构建（进阶 / 跨版本）
  python 中文补丁\patch\脚本\build.py --src "Sparrow安装目录" --install
  仅生成镜像不改动安装：
  python 中文补丁\patch\脚本\build.py --modules "原modules" --out modules.zh
  build.py 会自动完成：解包 jimage → 应用 FXML 字典 → 应用 Java 字典 →
  就地重建镜像 → 完美哈希与中文统计校验。全程只用 Python 标准库。

启动后效果：菜单 文件/视图/工具/帮助；欢迎页 新建钱包/打开钱包/导入钱包/
拖拽文件以打开；状态栏“未连接（点击右侧开关进行连接）”；设置、交易、
UTXO、多签、硬件钱包导入向导等全部对话框均为中文。


────────────────────────────────────────────
【便携版说明（重要）】
────────────────────────────────────────────
· 程序镜像内部不含任何绝对路径，配置文件也没有路径依赖；补丁脚本全部改为
  相对路径，按脚本自身位置推导程序根，因此“放到任意目录、任意盘符、任意
  电脑，解压即可用”。已实测带空格的陌生路径下中文界面完整生效。
· 钱包数据保存在当前用户目录（环境变量 %APPDATA%\Sparrow\，即
  “用户\<用户名>\AppData\Roaming\Sparrow”），不随程序目录移动；换机使用
  钱包时请一并复制其中的 wallets 文件夹。
· 若运行 .ps1 脚本提示执行策略限制，用：
  powershell -ExecutionPolicy Bypass -File "脚本名.ps1"

【三、汉化覆盖范围与术语口径】
────────────────────────────────────────────
实测覆盖（对原始镜像一次性应用最终 2359 条字典的确定结果）：
· 31 个 FXML，其中 27 个被改写（约 2700+ 中文字符）
· 439 个 Java 类、2444 处界面字面量替换
· 成品镜像 477 个资源含中文，共 20481 个中文字符
· 57359 个镜像资源完美哈希校验 0 失配
· 功能覆盖：钱包创建/打开/密码、账户导入导出、多签、交易/UTXO、设置、
  服务器连接、PayNym、消息签名、私钥清扫、助记词、24 款硬件钱包导入向导

术语口径（专名保留英文，通用词译中文）：
· 保留英文：Bitcoin / Taproot / Segwit / UTXO / PayNym / RBF / CPFP /
  PSBT / BIP39 / BIP32 / Tor / Electrum / Payjoin / Coldcard / Testnet 等
· 译为中文：Address→地址 / Balance→余额 / Status→状态 / Send→发送 /
  Receive→接收 / Settings→设置 / Sign→签名 等

有意保留英文（不译更安全、更利于排查）：
· SQL 语句、日期/数字格式串、颜色/CSS 样式
· 与外部值比较的错误串（Tor/服务器/协议诊断/硬件卡底层协议错误）
· Electrum / Bitcoin Core 服务端日志消息
这些不参与界面展示或仅出现在异常日志，保留英文不影响使用。

【四、汉化与修改事件记录】
────────────────────────────────────────────
[事件 1] 确认版本与结构
  用户提供 GitHub 链接并委托汉化。确认版本为 Sparrow 2.5.4，jpackage 打包，
  主体模块封装在 runtime\lib\modules（jimage 镜像），app\Sparrow.cfg 声明
  主模块 com.sparrowwallet.sparrow。软件无 i18n，确定直接改写镜像资源。

[事件 2] 解包与素材提取
  早期用 JDK 的 jimage 工具解包（124 模块，sparrow 模块 1380 个资源、
  31 个 FXML）。编写脚本扫描全部 Java 字面量与 FXML 文本，建立翻译候选清单。

[事件 3] FXML 界面中文化
  31 个 FXML 全部中文化；为避免 JavaFX 工具链解析问题，把注释块移到文件尾，
  保持 XML 结构合法。

[事件 4] Java 字面量翻译（六批字典，累计 2330 条）
  自写类常量池改写器 apply_java_trans.py：只替换未被类/方法/字段/描述符
  引用的 CONSTANT_Utf8，长度变化后重建常量池，绝不触碰标识符与字节码。
  六批字典人工审定（base 853 → 逐批补到 2330 条），每批后扫描残留英文，
  最终残留均为有意保留项（SQL/协议日志/专名）。

[事件 5] 镜像重建路线探索（jlink 路线被证伪）
  路线 A（jlink 整体重链接）：通过 verify 却在替换后启动失败
  （BootstrapMethodError→LambdaConversionException），A/B 对照证明与翻译
  无关，是 JDK 25.0.4.1 工具链与运行时 25.0.2 小版本不兼容，放弃。
  路线 B（就地改写 jimage，成功）：逆向 jimage 格式——小端、7 个 u4 头、
  perfect-hash（FNV）、location 属性编码、数据段按原始偏移排序；重建时
  redirect 表与字符串表保持字节不动，只重建 locations/offsets/data，改动
  资源以 raw 写入。verify 0 失配、启动稳定。

[事件 6] 镜像安装与界面验证
  多次装回并启动验证：菜单、欢迎页、状态栏、对话框均中文，日志仅汇率 WARN
  （离线环境，正常）。

[事件 7] 目录体积治理
  删除重复解包副本、jlink 失败产物、重复 JDK、源码包、临时镜像与截图等，
  并在工具链改为纯 Python 后移除不再需要的 JDK，最终目录约 540 MB。

[事件 8] 便携化与相对路径改造
  确认镜像/配置无绝对路径依赖；补丁脚本全部改为相对路径；实测带空格路径、
  zip 解压到新路径后启动中文完整，打包中文便携版 zip。

[事件 9] 纯 Python 一键工具链（关键升级，摆脱 JDK 依赖）
  为解决“每次版本升级都要重做、且依赖特定 JDK”的问题，把整条管线改造为
  纯 Python 标准库实现：
  · 新写 jimage_extract.py：解析 0xCAFEFAFA + zlib 压缩块，纯 Python 解包，
    对全部 1380 个压缩资源解压验证 0 失败，替代 JDK 的 jimage extract；
  · 把 apply_fxml_trans.py / apply_java_trans.py 重构为“函数 + 可单独运行”，
    修复常量池字段解析中一处 struct.unpack 缓冲区长度 bug；
  · 新写 build.py 一键编排：解包→FXML→Java→重建→校验→(可选)装回，
    支持自动探测、--src/--modules/--install-to/--clean 参数与交互模式；
  · 新增双击入口“一键汉化.bat”（自动找 Python）。
  端到端实测：从原始镜像全新构建，最终字典 2359 条、439 类/2444 处替换、
  477 资源含中文共 20481 字、完美哈希 0 失配。仓库只放 8 个分批明文字典，
  build.py 找不到总字典时按固定顺序自动合并，并内置“外部比较串黑名单”，
  强制保留 min relay fee not met 等节点错误原文以免破坏错误匹配；实测
  “总字典构建”与“分批自动合并构建”两条路径产物 SHA256 完全一致，双击入口
  与命令行产物也一致（确定性可复现）。最终镜像实际装回并启动，界面全中文、
  状态栏补翻、运行稳定。

[事件 10] 开源发布
  在 GitHub 创建公开仓库 EolusDev/sparrow-zh（Apache-2.0 衍生），分批推送

【五、升级到新版 Sparrow 怎么重新汉化】
────────────────────────────────────────────
工具链与版本号无关，新版无需逆向：
1. 装新版原版 Sparrow，运行 build.py 对其镜像构建（现有字典自动沿用）；
2. 运行 scan_remaining.py 扫描残留英文字面量；
3. 把“界面可见”的新文案补进 翻译字典\ 下对应的分批字典（FXML 补
   fxml_trans.json），结构 “英文原文”: “中文译文”，构建时自动合并；
4. 重跑 build.py。脚本幂等，可反复运行。
不可翻译项见第三节与 中文补丁\安装说明.md。

【七、常见问题】
────────────────────────────────────────────
1. 启动后窗口一闪而过/无界面？
   → 多为单实例锁残留，删除 %APPDATA%\Sparrow\sparrow.lock 后重试。

2. 如何追加/修改翻译？
   → 编辑 中文补丁\patch\翻译字典\ 下对应的分批字典（或本地合并出的
     java_trans_all.json），然后重跑 build.py（一条命令完成解包/翻译/重建）。
     与外部值比较的字符串不可翻译（build.py 已内置黑名单自动剔除）。

3. 想恢复英文原版？
   → 运行 还原.ps1，或把 modules.original.bak / backup\modules.original
     覆盖回 runtime\lib\modules（先退出 Sparrow）。

4. 一定要装 JDK 吗？
   → 不需要。构建只需要 Python 3.8+，解包/重建全部由 Python 标准库完成。

5. 日志里的汇率 WARN？
   → 汇率服务需联网，离线时的 WARN 属正常，不影响功能。
